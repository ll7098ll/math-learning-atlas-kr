# 연결과 위계 고도화 및 성능 개선 계획

작성일: 2026년 10월 29일

실행 현황: [연결과 위계 개선 구현 결과](연결과위계개선구현결과.md). 로딩 구조와 탐색 기능을 구현했으며, 위계 내용 확장과 독립 검토의 남은 범위를 구분해 기록한다.

연결과 위계를 포털의 핵심 탐색 기능으로 발전시킨다. 사용자가 어떤 개념을 선택하든 **어떤 기초가 필요한지, 무엇과 연결되는지, 이후 무엇으로 확장되는지, 왜 그런 관계인지**를 읽을 수 있어야 한다. 전체 교육과정에서의 위치와 특정 과제에서의 선수 조건을 구별하며, 빠른 화면 반응과 관계의 정확성을 함께 완료 조건으로 삼는다.

이번 산출물은 실행 계획이다. 아래 수치는 현재 로컬 코드와 데이터의 감사 결과이며, 개선 후 속도는 목표치다. 제품 코드와 배포는 변경하지 않았다.

## 현재 상태와 우선 해결할 문제

기존 [위계와 학습 순서 설계 계획](교육과정위계와학습순서설계계획.md)의 연구 원칙과 [시범 분석 결과](위계시범분석결과.md)를 이어받는다. 시범 구현은 이미 있으므로 다음 작업은 정확성 보완, 진입 속도 개선, 전체 개념으로의 탐색 확장이다.

| 확인 항목 | 현재 상태 | 다음 작업의 의미 |
|---|---|---|
| 전체 교육과정 분류 | 435개 성취기준, 46개 개념 묶음 | 전체 검색과 연결 탐색의 기반으로 활용 |
| 기존 관계 기록 | 전체 3,652개 중 성취기준 간 1,518개 | 하위 사고 등의 관계와 성취기준 간 연결을 구별 |
| 위계 시범 범위 | 3개 개념군, 6개 경로, 28개 사고, 32개 관계 | 전체 위계가 마련된 상태는 아님 |
| 위계에 대응된 성취기준 | 고유 12개 | 대응 여부와 해당 기준 전체의 위계 분석 완료를 구별 |
| 위계 검토 상태 | 32개 모두 수학적 자체 점검 초안 | 독립 검토와 학생 반응 검증은 별도 단계 |
| 메뉴 진입 | 세 시범 지도 중 하나를 바로 표시 | 46개 개념과 435개 기준에서 목표를 찾는 입구 필요 |
| 위계 로딩 | 약 2.64MB의 전체 관계 파일을 기다림 | 작은 위계 자료만 먼저 읽도록 분리 |
| 학교급 필터 | 범위 밖 조건과 목표를 숨김 | 필수 조건 누락과 목표의 임의 변경 방지 |

### 첫 수정에서 다룰 정확성 문제

1. **선택 목표가 범위 필터 때문에 바뀐다.** 현재 원래 목표가 숨겨지면 남아 있는 가장 깊은 노드를 새 목표로 삼는다. 비율 지도에서 고등학교만 선택할 때에도 사용자가 선택한 목표는 유지되어야 한다.
2. **함께 필요한 조건의 일부가 사라진다.** 비율 지도에서 중학교만 선택하면 두 조건으로 이루어진 묶음이 한 조건만 남을 수 있다. 현재 화면은 남은 조건만 세어 전체 묶음처럼 표시한다. 원래 조건 수와 범위 밖 조건을 보존해야 한다.
3. **의미 확장과 필요 조건이 같은 AND 묶음에 들어 있다.** 정비례의 `R-direct-invariant`는 두 유형을 함께 묶고 있다. 관계 자체의 타당성을 다시 검토하고, 의미 확장 선이 필수 선수 조건으로 읽히지 않도록 분리한다.
4. **탐색 상태가 초기화된다.** 지도 탭 변경은 학교급 범위를, 범위 적용은 선택한 설명 경로와 노드 등을 잃을 수 있다. 유효한 선택은 유지하고, 유지할 수 없는 선택만 이유와 함께 해제한다.
5. **모바일 노드와 선의 배치 기준이 다르다.** 선은 600px 이하에서 세로 배치로 바뀌고 CSS의 단일 열 전환은 520px 이하다. 521~600px 구간을 포함해 같은 배치 기준을 쓰도록 한다.

## 목표로 하는 탐색 경험

사용 흐름은 **개념 찾기 → 목표 수행 선택 → 기초와 확장 살펴보기 → 관계의 이유 확인 → 다른 목표나 경로로 이동**이다.

| 화면 | 제공할 경험 | 완료 조건 |
|---|---|---|
| 연결과 위계 시작 | 개념명·성취기준 코드 검색, 46개 개념 묶음, 최근 목표, 분석 범위 표시 | 435개 모든 기준에서 기존 연결에 접근 가능 |
| 개념 연결 보기 | 학교급을 넘는 의미 연결·확장·대조를 탐색 | 같은 학년이거나 같은 단어라는 이유만으로 선수 관계를 만들지 않음 |
| 과제별 위계 보기 | 선택한 목표에 필요한 기초, 함께 필요한 조건, 대안 경로, 이후 확장 | 목표 수행과 적용 경로가 명시됨 |
| 관계 설명 | 왜 필요한가, 어떤 조건에서 성립하는가, 새로 필요한 사고는 무엇인가 | 지도에서 한 번의 선택으로 설명 확인 가능 |
| 경로 비교 | 두 경로의 공통 기초와 서로 다른 조건을 나란히 비교 | 한 경로의 조건을 다른 경로에 강제하지 않음 |

처음에는 선택 목표의 직접 연결을 보여주고, 사용자가 이전·이후 한 단계씩 펼친다. 노드 클릭은 설명을 열며, 별도의 **이 개념을 목표로 보기** 동작으로 중심을 바꾼다. 목표 변경은 주소와 뒤로 가기에 반영한다.

기본 배치는 기초 → 선택 목표 → 이후 확장이다. 함께 살펴볼 의미 연결은 별도 영역이나 보조선으로 둔다. 목표와의 실제 선행·후행 관계를 계산하여 배치하고, 단계 번호가 앞선다는 이유만으로 선수 조건이라 표시하지 않는다.

학교급 필터는 범위 밖 맥락을 접거나 약하게 표시하는 방식으로 설계한다. 원래 목표와 필요한 경계 노드는 남기며, 조건 묶음에는 ‘전체 2개 중 1개가 범위 밖’처럼 표시한다. 숨긴 단계를 뛰어넘는 새 화살표는 만들지 않는다.

AND는 함께 필요한 조건이 합류하는 묶음으로, 대안 경로는 서로 선택 가능한 경로 카드로 표현한다. 정비례와 반비례처럼 목표가 다른 분기와, 같은 목표를 설명하는 두 대안 풀이를 구별한다. 모든 경로 선택을 같은 목표의 OR 조건으로 취급하지 않는다. 아직 분석되지 않은 구간은 ‘위계 미검토’로 표시한다. 선이 없다는 사실을 ‘선수 개념 없음’으로 해석하지 않는다.

데스크톱에서는 노드를 선택해도 지도 위치를 유지하고 옆 설명을 갱신한다. 모바일은 세로 흐름과 접이식 설명을 제공한다. 색상과 선 종류 외에도 관계 이름을 표시하고, 키보드로 지도와 근거를 왕복할 수 있게 한다.

## 관계 데이터와 검토 체계

### 교육과정 위치와 학습 관계를 분리

공식 성취기준, 여러 기준에 걸치는 개념, 특정 과제의 목표 수행·사고 요소를 별도 대상으로 둔다. 하나의 개념이 여러 성취기준에 대응할 수 있고, 하나의 기준에도 여러 목표가 있을 수 있다. 현재 시범의 3m 분배 같은 구체 과제 노드를 곧바로 보편적인 개념 노드로 바꾸지 않는다.

| 관계 | 화면에서 허용하는 주장 | 순서 계산 |
|---|---|---|
| 과제별 필요 조건 | 이 수행과 경로에서 함께 필요한 사고 | 조건 묶음과 적용 범위를 검토한 경우 사용 |
| 학습 지원 | 이해를 돕는 사고나 경험 | 필수 선수로 처리하지 않음 |
| 의미 연결·대조 | 공통점과 차이, 비교할 이유 | 학습 선후 계산에서 제외 |
| 의미 확장 | 무엇을 유지하며 무엇이 추가되는가 | 확장 보기의 방향으로만 사용 |
| 수업 순서 제안 | 선택한 수업에서 제안하는 진행 | 해당 수업 경로 안에서만 사용 |
| 병렬·동시 발달 | 순서를 고정하지 않고 함께 다룰 대상 | 순서를 강제하지 않음 |

과제별 필요 조건은 선택한 풀이의 논리적 의존을 나타낸다. 해당 사고를 수업 전에 완전히 숙달해야 한다는 뜻은 아니며, 과제 안에서 함께 구성할 수도 있다. 선행 숙달을 주장하려면 별도의 근거와 적용 조건을 요구한다.

기존 관계의 유형과 ID는 보존하고 새 판정과 대응 정보를 추가한다. 학년, 코드 번호, 연결 수로 필수 선수 관계를 자동 결정하지 않는다.

### 관계별로 기록할 정보

- 출발·도착 개념과 목표 수행, 대응 성취기준, 관계 종류와 방향.
- 적용 과제, 수 범위, 표현 방식, 경로와 성립 조건.
- 조건 묶음의 전체 구성원, AND·OR 구분, 목표와의 대응. 묶음은 화면에서 보이는 선으로 재계산하지 않는다.
- 연결 이유, 추가로 필요한 사고, 다른 해결 경로와 반례.
- 근거의 정확한 위치와 적용 범위. 공식 문서, 수학적 분석, 연구 결과, 수업 제안을 구별한다.
- 확인 질문, 기대 설명, 관찰할 오류와 후속 질문.
- 작성·검토 이력과 미해결 쟁점. 근거 종류, 수학적 검토, 교육적 검토, 학생 반응 검증 상태는 별도로 기록한다.

32개 시범 관계부터 이 구조로 점검한다. 모든 관계를 일괄 승인하지 않고, 과제별 필요성·대안 경로·조건 묶음·목표 분해가 타당한지 확인한다. 진단 질문은 학생의 사고를 확인하는 자료로 제공하며, 검증 전에는 자동 숙달 판정에 사용하지 않는다.

### 전체 교육과정으로 확장하는 순서

1. **기존 세 개념군을 기준 사례로 완성한다.** 분수의 두 분배 경로, 정비례와 반비례, 넓이의 분할과 복제 경로에서 데이터·화면·검토 절차를 확정한다.
2. **기준 사례의 연결 경계부터 확장한다.** 분수와 소수·연산, 비와 비례·문자식·함수, 넓이와 측정·도형 성질의 후보를 우선 검토한다. 이는 분석 대상의 우선순위이며 확정된 학습 사슬은 아니다.
3. **초중고 전환을 포함하는 6~10개 개념 묶음으로 넓힌다.** 실제 검토 난이도와 관계 밀도를 확인한 뒤 범위를 확정한다. 기존 46개 분류에 대응시키고, 학생 반응 자료가 필요한 관계는 별도 검증 과제로 둔다.
4. **46개 전체에 조사 현황을 제공한다.** 연결 제공, 위계 후보 작성, 수학적 검토, 교육적 검토, 학생 반응 검증을 따로 집계한다. 전체 분류율을 위계 검토 완료율로 표시하지 않는다.

개념군별 완료 조건은 목표 수행 분해, 관계별 이유·조건·대안·진단 자료, 참조 무결성, 조건 묶음 검증, 해당 순서 관계의 순환 점검, 검토 이력이다. 관계 수를 채우기 위해 근거가 약한 연결을 추가하지 않는다.

## 긴 로딩의 진단과 개선

### 확인한 구조와 아직 측정할 항목

현재 `app.js`와 `explore.mjs`는 위계 진입 전에 `connections.json`을 기다린다. 파일은 **2,636,613바이트**, 그 안의 시범 위계는 **33,143바이트**다. 시범 위계와 전체 출처, 실제 참조하는 기존 관계 7개만 묶으면 **47,368바이트**다. 현재 자료를 선별해 계산한 값이며 아직 분리 구현은 하지 않았다.

위 수치는 압축 전 파일 크기다. 서버의 실제 압축·전송 크기는 별도로 측정해야 한다. 비인증 배포 요청은 401로 끝나므로 해당 응답 시간을 실제 사용자 로딩 시간으로 사용할 수 없다.

메모리의 Promise 캐시는 이미 있어 같은 탭에서 다시 들어갈 때 반드시 전체 파일을 다시 받는 구조는 아니다. 따라서 첫 진입과 재진입의 지연을 따로 재현한다. `fetch`의 `no-cache`는 저장 금지가 아니라 서버 재검증을 뜻하므로, 이를 매번 전체 재다운로드하는 원인으로 단정하지 않는다. [MDN의 Request cache 설명](https://developer.mozilla.org/en-US/docs/Web/API/Request/cache).

### 먼저 재현하고 시간을 나누어 측정

로그인된 실제 배포 화면과 로컬 화면에서 다음 경우를 구별한다.

- 첫 방문 후 메뉴 클릭과 위계 직접 링크로 첫 진입.
- 같은 탭에서 재진입, 상세 화면을 먼저 읽은 후 진입.
- 개념군·설명 경로·학교급 범위 변경.
- 빠른 메뉴 연속 선택, 요청 실패와 재시도, 이전 버전이 열린 탭.
- 데스크톱과 모바일, 네트워크·CPU를 제한한 환경.

측정 구간은 **선택 → 화면 틀 표시 → 요청 시작 → 응답 시작 → 다운로드 끝 → JSON 해석 끝 → 노드 표시 → 선 표시와 조작 가능**으로 나눈다. 네트워크 대기, 파일 크기, 화면 계산 시간을 각각 기록한다. 원시 크기·압축 크기·전송 크기와 응답 시간을 구별할 때는 [Resource Timing API](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceResourceTiming)를 사용한다.

재진입에도 느리다면 네트워크 이외에 전체 화면 재생성, 레이아웃 계산, 선 다시 그리기, 오래된 요청의 화면 덮어쓰기를 조사한다. 현재 시범 규모에서 복잡한 그래프 계산을 주원인으로 단정하지 않는다.

### 데이터 분리와 화면 표시 순서

| 단계 | 개선 | 확인할 결과 |
|---|---|---|
| 첫 수정 | 위계 전용 약 47KB 묶음을 생성하여 전체 관계 파일 의존성 제거 | 위계만 열 때 `connections.json` 요청 0회 |
| 화면 반응 | 제목·검색·현재 목표·필터를 먼저 표시하고 지도 영역만 준비 상태로 둠 | 전체 본문이 로딩 문구로 오래 가려지지 않음 |
| 규모 확대 | 위계 목록, 개념군별 지도, 관계 상세 근거를 분리 | 선택한 범위의 자료만 읽음 |
| 연결 탐색 | 기준·개념별 관계 색인과 상세 근거 묶음을 생성 | 기존 관계와 출처의 접근성을 보존 |
| 실패 처리 | 늦거나 실패한 근거 패널에 개별 재시도 제공 | 이미 표시된 지도 탐색은 계속 가능 |

기존 정적 사이트 구조와 빌드 생성기를 활용한다. 전체 관계를 서버에서 매번 계산하거나 새 그래프 시스템으로 옮기는 작업은 실제 측정에서 필요성이 확인될 때 검토한다.

### 캐시와 갱신 일관성

최신 버전을 확인하는 작은 목록과, 내용이 고정된 버전별 자료를 구별한다. 버전별 파일 경로 또는 콘텐츠 해시를 이용해 같은 주소의 내용을 바꾸지 않는 방식으로 설계하고, 현재 버전 불일치 검사는 유지한다. 호스팅의 실제 응답에서 압축과 캐시 헤더 지원을 확인한다.

성공한 요청과 진행 중인 요청을 공유하는 메모리 캐시는 유지한다. 선택 변경 시 오래된 결과가 새 화면을 덮지 않게 하고, 공유 요청을 취소할 때 다른 화면에서 필요한 자료까지 취소하지 않도록 한다. 메뉴에 초점을 두거나 첫 화면 작업이 끝난 뒤 작은 위계 자료만 미리 읽는 방식은 데이터 분리 이후에 검토한다.

### 렌더링 개선

성취기준·관계 ID 조회표와 노드별 입출력 목록을 만들어 반복 탐색을 줄인다. 노드 위치는 프레임당 한 번 읽고 선을 한 번 갱신한다. 학교급·경로·선택 변경은 필요한 영역을 갱신하고, 지도 전체 크기와 DOM 수는 단계별 펼치기로 제한한다. Worker, 가상화, 그래프 라이브러리 교체는 이 개선 이후의 측정 결과로 결정한다.

### 성능 완료 기준

아래는 초기 목표다. 첫 계측 때 기준 기기·브라우저를 기록하고, 네트워크 하향 1.6Mbps·상향 750Kbps·지연 150ms·CPU 4배 제한을 별도 시험 조건으로 고정한다. 조건별 30회 이상 측정하여 중앙값과 p95를 기록한다. 인증 화면 자체의 대기는 구별하되, 자료 요청 중 발생하는 인증·호스팅 지연은 포함한다.

| 지표 | 초기 목표 |
|---|---|
| 메뉴 선택 후 제목·조작부 등 첫 반응 | p95 100ms 이내 |
| 메모리에 자료가 있는 재진입·경로 변경 후 지도 조작 가능 | p95 200ms 이내 |
| 제한된 모바일 조건에서 메뉴 선택 후 첫 유용한 지도 | p95 1.5초 이내 |
| 위계 직접 링크의 첫 진입 | 문서 탐색부터 별도 측정하며 첫 계측 후 목표 확정 |
| 현재 시범의 위계 전용 원시 데이터 | 60KB 이하 |
| 위계만 보는 동안 전체 관계 묶음 요청 | 0회 |

첫 반응에는 로딩 틀도 포함될 수 있으므로 그것만으로 완료하지 않는다. 노드와 관계를 읽고 조작할 수 있는 시점을 함께 통과해야 한다. 위 목표는 프로젝트의 제안 기준이며 웹 표준의 합격 기준을 인용한 수치가 아니다.

## 실행 순서와 산출물

성능 개선과 관계 검토는 병렬로 진행할 수 있다. 새 위계 화면은 관계 유형과 조건 묶음의 의미를 먼저 확정한 뒤 연결한다.

| 순서 | 작업 | 산출물과 완료 조건 | 예상 집중 작업량 |
|---|---|---|---|
| 1 현재 문제 재현 | 최초·재진입 계측, 목표 대체·부분 AND·상태 초기화 재현 | 측정 기준표와 재현 사례 | 0.5~1일 |
| 2 우선 수정 | 위계 데이터 분리, 화면 틀 우선 표시, 목표·조건 보존, 탐색 상태·모바일 기준 수정 | 속도 목표 비교, 의미가 바뀌는 회귀 사례 해소 | 2~3일 |
| 3 관계 구조와 통합 탐색 | 개념·목표·관계·조건 묶음 정리, 전체 검색 입구, 목표 중심 보기 | 기존 자료를 보존한 변환과 전체 탐색 가능 | 3~5일 |
| 4 시범 완성 | 세 개념군 재검토, 경로 비교, 근거·진단 화면, 사용자 평가 | 세 개념군에서 공통 검증 과제 통과 | 개발·내용 작업 3~5일 및 독립 검토 일정 |
| 5 주요 개념군 확장 | 6~10개 묶음의 목표 분해·관계 검토·화면 연결 | 개념군별 검토 기준과 상태 공개 | 시범의 실제 검토 단가로 산정 |
| 6 전체 운영 | 46개 묶음 조사 현황, 검토 대기 목록, 갱신·회귀 점검 | 범위와 근거를 지속해서 추적 가능 | 확장 범위에 따라 산정 |

첫 네 단계는 약 8.5~14 집중 작업일의 계획 범위다. 독립 검토자 일정과 학생 반응 검증은 별도다. 전체 435개 기준의 위계를 검토 완료로 만드는 일정은 시범에서 실제 검토량을 확인한 뒤 산정한다.

## 검증과 공개 기준

현재 네 자동 검사 모두 통과했다. 검사는 자료 보존, 참조, 범위, 경로 등의 회귀를 확인하지만 실제 클릭 지연과 부분 조건 묶음의 오해까지 보장하지 않는다.

- `node scripts/test_portal_refactor.mjs`: 435개 상세, 학교급·15과목, 전체 관계, 버전과 기존 링크.
- `node scripts/test_concept_flows.mjs`: 46개 개념, 435개 주 분류, 1,518개 성취기준 간 관계의 접근성.
- `node scripts/test_hierarchy.cjs`: 세 개념군·여섯 경로, 참조·조건 묶음·순환 거부.
- `node scripts/test_portal_scope.cjs`: 여섯 범위와 36개 범위·경로 조합.

구현 단계에서는 다음 의미와 행동을 추가로 검사한다.

| 검증 영역 | 필수 확인 |
|---|---|
| 관계 의미 | 의미 확장이 필수 선수로 승격되지 않음, 수업 제안이 보편 순서로 표시되지 않음 |
| 검토 상태 | 검토 완료로 바뀔 때 검토자·근거·판정 이력을 요구하며, 모든 상태를 미검토로 고정하는 기존 검사를 갱신 |
| 조건 묶음 | 범위 밖 조건도 전체 구성에 남음, 다른 경로의 조건이 섞이지 않음 |
| 목표와 주소 | 필터 후 목표 유지, 경로·범위 보존, 직접 링크·뒤로 가기·새로고침 복원 |
| 분리 자료 | 모든 기존 관계와 출처 보존, 대상 ID·버전 일치, 위계의 전체 관계 다운로드 제거 |
| 실패와 경쟁 요청 | 개별 재시도, 구버전 처리, 빠른 이동 후 오래된 화면 덮어쓰기 없음 |
| 실제 화면 | 360·520·560·600·768·1280px에서 선·노드 일치, 페이지 넘침 없음, 키보드 탐색 가능 |
| 속도 | 최초·재진입·경로 전환의 측정 조건과 원시 결과를 남기고 목표와 비교 |

사용자 검토에서는 목표에 필요한 기초 찾기, 두 경로의 차이 설명하기, 관계의 이유 찾기, 학교급을 바꿔도 원래 목표로 돌아오기를 수행한다. 첫 시범에서는 교사·실사용자 3~5명에게 설명 없이 수행하게 하고, 완료 시간·오해·막힌 지점을 기록한다. 과제 성공률 80% 이상을 초기 목표로 삼되, 필수 조건과 선택 경로를 뒤바꾸는 오해가 발견되면 해당 표현을 고친 후 다시 확인한다. 이 사용성 점검을 학생의 학습 효과 검증으로 표시하지 않는다.

단계별로 같은 버전의 생성 자료를 준비하고, 시험 환경에서 비교한 뒤 반영한다. 이전 배포와 데이터 묶음을 함께 보관해 문제 발생 시 같은 버전으로 되돌릴 수 있게 한다. 속도 개선으로 기존 관계 근거가 빠지거나, 화면 개선으로 검토 상태가 올라가는 일이 없어야 한다.
