# 수학 교육과정 탐색 포털 UI·UX 재설계 계획

2026년 11월 19일 · 설계 제안

**첫 화면을 ‘교육과정 탐색’으로 바꾼다.** 수업을 준비하는 교사가 학교급과 학년군·과목을 선택하면 그 범위의 내용 체계와 성취기준을 바로 읽을 수 있게 한다. 코드를 아는 사람은 검색 한 번으로 같은 기준에 도착한다. 포털의 강점인 진단 과제와 연결 지도는 기준을 읽다가 “무엇을 관찰할까?”, “앞뒤 학년에서는 어떻게 다룰까?”라는 질문이 생기는 위치에서 연다.

## 사용자가 하려는 일과 화면 순서

주 사용자는 교사와 예비교사로 가정한다. 교육과정 용어를 모르는 방문자에게는 학교급과 일상적인 검색어로 들어가는 길을, 연구자에게는 코드·개념군·기존 공유 주소로 곧바로 들어가는 길을 제공한다. 실제 사용성 조사에서 이 우선순위를 확인한다.

| 사용자가 하려는 일 | 제안하는 여정 | 성공한 순간 |
| --- | --- | --- |
| 내 수업의 공식 범위 찾기 | 교육과정 탐색 → 초등 → 5~6학년군 → 수와 연산 → 성취기준 | 목록에서 원문을 읽고 `6수01-10`의 PDF 31쪽·인쇄 25쪽을 찾는다. |
| 한 학년군의 큰 그림 읽기 | 같은 범위에서 ‘내용 체계’ → 핵심 아이디어 또는 과정·기능 → 관련 성취기준 | 공식 항목의 적용 범위와 연구자가 연결한 개별 기준을 구별해 설명한다. |
| 코드나 단어로 바로 찾기 | 첫 검색창에 `6수01-10` 또는 ‘분수’ → 원문 미리보기 → 결과로 복귀 | 정확한 코드는 첫 결과에 뜬다. 단어 검색에서는 다른 결과를 계속 읽을 수 있다. |
| 학교급 전환이나 수업 계열 검토 | 수와 연산 → ‘두 범위 비교’ → 초등 3~4와 5~6을 선택 → 양쪽 기준 열기 | `4수01-09`와 `6수01-10`의 문구 차이를 읽고 같은 비교 화면을 동료와 공유한다. |
| 수업 과제 또는 연구 근거 확인 | 기준 상세 → ‘수업 과제’에서 하나 선택 → 목표·경로별 조건 → ‘연결과 근거’ | 과제의 적용 목표, 한 경로에서 함께 필요한 조건, 가능한 다른 경로와 문헌이 뒷받침하는 범위를 찾는다. |

## 메뉴와 화면 배치

주 메뉴는 **교육과정 탐색 · 비교 · 연결 지도 · 자료 안내**로 구성한다. 검색은 탐색 화면의 눈에 보이는 입력창으로 제공한다. ‘비교’는 목록에서 고른 대상을, ‘연결 지도’는 상세에서 읽던 기준을 이어받는다. 빈 상태로 직접 들어온 경우에는 각각 범위 선택과 개념군 선택을 먼저 보여준다.

| 화면 | 데스크톱 | 휴대폰 |
| --- | --- | --- |
| 교육과정 탐색 | 첫 줄에 코드·키워드 검색. 그 아래 초등·중학교·고등학교를 고르면 바로 학년군 또는 과목이 열린다. 선택 후 왼쪽은 범위, 본문은 영역별 원문 목록으로 쓴다. | 학교급 선택 후 학년군·과목을 한 열에서 고른다. 선택이 끝나면 상단에 ‘초등 5~6 · 수와 연산’과 ‘범위 변경’을 남기고 목록을 올린다. |
| 학년군·과목 한눈에 | 제목에 범위와 판본, 아래에 ‘성취기준 / 내용 체계’ 전환을 둔다. 기준은 교육과정 순서로 묶고, 내용 체계는 ‘핵심 아이디어’, ‘지식·이해’, ‘과정·기능’, ‘가치·태도’ 네 범주로 읽는다. | 같은 순서를 사용한다. 범위 필터는 시트에서 한 번에 변경한다. 결과 수와 선택 해제는 목록 머리에 둔다. |
| 성취기준 읽기 | 목록에서 짧게 읽을 때는 옆 패널에 원문·쪽수·‘전체 상세’를 보여준다. 전체 상세는 고유 주소를 가진 읽기 화면이다. 본문 오른쪽 목차에서 ‘공식 원문과 범위 / 분석 / 수업 과제 / 연결과 근거’로 이동한다. | 기준을 누르면 전체 너비 읽기로 이동한다. 첫 화면에 코드·원문·출처가 들어오도록 하고, 접힌 ‘이 문서의 목차’에서 원하는 절로 건너뛴다. |
| 두 범위 비교 | 두 열 머리에 각각 학년군·과목명을 고정하고 같은 공식 영역 안에서 양쪽의 원문 목록을 독립적으로 읽는다. 사용자가 고른 기준 두 개는 코드와 원문, 쪽수 기준으로 나란히 본다. | ‘원문’, ‘범위와 출처’ 같은 항목 아래 두 대상을 차례로 배치한다. 가로 스크롤 없이 차이를 읽을 수 있다. |
| 연결 지도와 자료 안내 | 연결 지도는 선택 기준 주변의 관계 목록부터 열고, 원하면 46개 개념군과 전체 연결망을 펼친다. 자료 안내에서 고시 판본, 읽은 문헌 범위, 검토 상태, 통계 실험실과 탐구 워크북에 접근한다. | 같은 관계를 텍스트 목록으로 끝까지 읽을 수 있다. 그래프 확대·이동은 별도 보기에서 제공한다. 통계 자료에는 가상·모형 계산·공개 관측의 출처 유형을 유지한다. |

초등은 세 학년군, 중학교는 1~3학년군, 고등학교는 공통·일반 선택·진로 선택·융합 선택 아래 15과목으로 구성한다. 고교 기본수학의 대체 이수 안내를 과목 선택 시점에 표시한다. 다른 고교 과목끼리 영역 체계가 다르면 각 과목의 명칭과 순서를 그대로 보여준다. 빈 대응 칸에는 ‘이 범위에 해당 항목 없음’을 표시하고, 비교 화면의 행 정렬은 학습 선후를 표현하는 데 사용하지 않는다. [데이터 안내](DATA.md)

과목을 처음 맡은 교사를 위해 제목 곁에 ‘이 교육과정 이해하기’를 둔다. 성격과 목표, 교수·학습 및 평가를 읽을 수 있도록 해당 과목의 원문 쪽수를 확인해 연결한다. 교사가 곧장 수업 범위를 찾는 날에는 이 개요를 열지 않고도 목록을 사용할 수 있다.

### 대표 상세 화면에 들어갈 실제 내용

| 위에서 읽는 순서 | `6수01-10`에서 보이는 내용 |
| --- | --- |
| 돌아갈 곳 | 검색에서 왔으면 ‘분수 검색 결과로’, 학년군에서 왔으면 ‘5~6학년군 수와 연산으로’. 직접 링크 방문자는 해당 영역 목록으로 이동한다. |
| 위치와 원문 | 초등학교 › 5~6학년군 › 수와 연산. 코드, 공식 문장, 교육부 고시 제2022-33호, ‘PDF 31쪽 열기’와 인쇄 25쪽을 한 묶음으로 둔다. |
| 수업 준비 | ‘나눗셈의 몫을 분수로 나타내기’는 탐색용 제목이다. ‘수업 과제’를 열면 3 m의 끈을 네 사람이 같은 길이로 나누는 **자체 설계 과제**와 학생에게 설명을 요청할 지점이 나온다. |
| 더 읽기 | 상세 분석의 12절과 기존 절 링크를 새 목차에서 계속 열 수 있게 한다. ‘연결과 근거’에서는 관계의 종류, 대상 목표, 근거가 뒷받침하는 범위를 함께 읽는다. |

공식 원문, 자체 분석, 문헌 주장, 독립 검토, 학생 검증은 해당 항목 곁에 텍스트로 표시한다. 연구 검토 원장의 실제 독립 검토와 학생 반응 검증은 각각 0건이다. 과제를 볼 때에는 해당 목표와 경로를 먼저 선택하고 ‘이 경로에서 모두 필요한 조건’을 한 묶음으로 읽는다. 대안은 별도 경로로 열고, 읽은 항목에 숙달·완료 표시를 붙이지 않는다. [대표 기준 상세](../analyses/6수01-10.md) · [현재 연구 상태](STATUS.md)

## 시각 언어와 컴포넌트

현재 사이트의 짙은 청록을 선택·링크·포커스의 중심색으로 쓴다. 원문은 밝은 바탕, 넓은 본문 폭과 선명한 한글로 읽게 한다. 목록은 가는 구분선으로 나누고, 카드 테두리는 과제처럼 독립된 묶음에 사용한다. 본문은 시스템 한글 글꼴 16~18px, 줄 높이 약 1.65, 상세 본문 폭 640~760px를 출발값으로 잡는다. 코드·쪽수·분수식은 좁은 화면에서 줄바꿈과 확대를 실제 확인한다.

| 사용자 동작 | React·shadcn/ui 조합 | 적용 규칙 |
| --- | --- | --- |
| 범위 선택·검색 | 링크/버튼, Input, Select 또는 검색 가능한 Combobox, 모바일 Sheet | 세 학교급은 이름이 보이는 선택지로, 15과목은 검색 가능한 목록으로 제공한다. 한글 조합 입력 완료를 기다린다. 코드의 대괄호·공백을 허용하고 정확한 코드, 제목, 원문 일치 순으로 결과를 정렬한다. |
| 범위 안에서 읽기 | Breadcrumb, Tabs, Accordion, 의미 있는 HTML 제목·목록 | Tabs는 두 자료 보기 전환에 쓴다. 원문을 목록에서 바로 읽고, 해설만 선택해서 펼칠 수 있게 한다. 패널을 닫으면 호출한 행으로 포커스가 돌아간다. |
| 비교·공유·인쇄 | 비교 대상 추가 버튼, Table, 작은 화면의 항목별 목록, DropdownMenu | 두 대상의 이름·교체·삭제를 명시한다. 공유 주소에는 범위, 기준 코드, 선택 절을 담는다. 인쇄물에 코드·판본·쪽수·자료 성격을 넣는다. |
| 과제와 근거 읽기 | 제목이 있는 section, Accordion, 텍스트 라벨, 근거 링크 | 공식 문장과 자체 과제를 각각 명명한다. 관계의 설명과 검토 상태는 색 또는 마우스 호버에만 의존하지 않는다. |
| 결과 대기·없음·오류 | Skeleton, 상태 텍스트, Alert와 재시도 버튼 | 목록이 비면 ‘영역 해제’와 ‘전체 범위에서 검색’을 제공한다. 상세 요청이 실패해도 읽던 목록은 유지한다. 데이터 버전이 바뀌면 새로고침 후 동일 주소로 돌아온다. |

Tailwind에는 글자·간격·색·포커스·화면 분기 값을 공통 테마로 두고 shadcn/ui는 실제 사용자 동작별로 가져온다. 탭·시트의 키보드 이동, Esc로 닫기, 명확한 포커스, 상태 낭독, 일반 본문 대비 4.5:1, 320px 너비에서의 줄바꿈을 검증한다. 주 터치 조작의 설계 목표는 44px 이상이다. [shadcn/ui 구성](https://ui.shadcn.com/docs/installation/vite) · [Tailwind와 Vite](https://tailwindcss.com/docs/installation/using-vite) · [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## 구현 순서와 완료 기준

계획용 추정은 프런트엔드 개발자 1명과 교육과정 검토자가 협업하는 **5~7주**다. 첫 2주는 탐색·읽기 시범과 교사 관찰에 집중한다. 사용자 모집과 현행 저술 환경 동기화 일정에 따라 조정한다.

| 단계 | 작업과 산출물 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| 1주차 · 현재 흐름과 화면 설계 | 기존 메뉴·URL·12절·도구의 이동 대응표, PC·휴대폰 와이어프레임, 현행 사이트 과제별 기준 시간. 대표 자료로 초등 분수, 중학교 변화와 관계, 고교 공통수학·기본수학을 고른다. | 대상별 학년군·과목 표시와 원문·과제의 구별을 교육과정 검토자가 확인한다. 같은 과제로 전후 비교할 수 있다. |
| 2주차 · 동작 시범과 사용성 평가 | React + TypeScript + Vite로 탐색 → 원문 → 과제 → 목록 복귀를 관통하는 시범을 만든다. 초·중·고 교사와 예비교사를 포함해 5명 안팎이 현행과 시범에서 같은 난도의 과제를 수행한다. | 진행자 도움 없이 5명 중 4명 이상이 지정 기준과 원문 쪽수를 1분 안에 찾는 것을 1차 목표로 삼는다. 원문과 자체 과제를 혼동한 사례는 문구·배치를 수정해 재확인한다. |

### 데이터와 배포에서 필요한 작업

1. **자료 조회와 UI를 나눈다.** 기존 `store.mjs`의 카탈로그·기준별 상세·기준별 관계 조회, 캐시와 버전 검사를 재사용한다. 홈에서는 전체 관계·흐름·목표 그래프 요청 0건을 목표로 한다. 첫 진입과 상세 진입의 요청 수, 압축 전송량, 첫 원문 표시 시간을 같은 기기·네트워크 조건에서 전후 측정한다. [조회 모듈](../site/dist/modules/store.mjs) · [기존 프로젝트에 React 도입](https://react.dev/learn/add-react-to-an-existing-project)
2. **내용 체계용 색인을 원장에서 만든다.** 공식 항목의 ID·범주·적용 범위·원문 쪽수는 구조 원장에서, 연구자가 대조한 기준·목표 연결은 검토 원장에서 가져온다. 571개 내용 체계 항목과 571개 명시적 과제에는 서로 다른 ID와 제목을 사용한다. 학년군 공동 적용 항목은 원래 범위를 함께 표시한다. [구조 원장](../data/curriculum_structure.json) · [대응 검토 원장](../data/curriculum_mapping_reviews.json)
3. **UI의 편집 원본과 정적 빌드를 확보한다.** 버전 관리되는 UI 소스에서 별도 스테이징 경로로 빌드하고 저술 환경의 앱 원본과 동기화한다. 내보내기는 Vite 매니페스트가 가리키는 JS·CSS·분할 자산까지 포함하게 한다. 기존 `#view=…` 주소와 절·과제 링크를 유지한다. PDF 기본 주소는 배포 환경별로 지정하고 쪽수 앵커를 검사한다. [개발 안내](DEVELOPMENT.md) · [현재 내보내기](../scripts/export_portal_snapshot.py) · [Pages 배포 설정](../.github/workflows/checks.yml) · [Vite 정적 배포](https://vite.dev/guide/static-deploy.html)
4. **데이터 회귀 검사와 화면 동작 검사를 함께 둔다.** 저술 환경에서 새로운 경로로 스냅샷을 내보낸 뒤 `dist/`·`tests/`·`snapshot.json`을 한 단위로 검토한다. `python scripts/check_repository.py`, `python scripts/export_portal_snapshot.py --verify`, 기존 `test_content_objects.mjs`·`test_goal_network.mjs`·`test_catalog_groups.mjs`와 변경한 경로의 모델 검사를 실행한다. 기존 HTML 문구에 의존하는 목록 검사는 새 화면의 행동 검사와 대조해 갱신한다. 브라우저에서는 로컬 루트·GitHub Pages 하위 경로의 공유 주소, 모바일 필터, 원문 PDF, 과제·워크북·CSV를 확인한다. 이전 배포 파일은 함께 복구할 수 있는 단위로 보관한다.
