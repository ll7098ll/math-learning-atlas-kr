# 문서 정비 계획과 후속 과제

기준일: 2026-11-18. 이번 작업은 최신 로컬 자료를 설명하는 문서와 GitHub 업로드 기반을 마련하는 범위입니다. 연구 전체의 완료 조건은 [현재 상태](STATUS.md)와 [전체 자료 보완 진행](전체자료보완진행.md)에 별도로 기록합니다.

## 이번 정비 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1. 현황 확인 | 원본·검사 기록·배포본·중첩 Git 위치 대조 | 최신 로컬과 공개 버전을 구분 |
| 2. 문서 체계 | README, 전체 문서 안내, 상태·변경 기록, 개발·데이터·기여 안내 | 현재 읽을 문서와 누적 이력의 역할을 표시 |
| 3. 실행 파일 보존 | 현재 포털의 참조 자산만 `site/`로 복사 | 기존 작업본 보존, 파일 해시 대조 |
| 4. GitHub 기반 | ignore·인코딩·이슈·PR·CI·자료 권리 안내 | 임시 파일·중첩 저장소·기본 제외 원문이 Git 후보에 없음 |
| 5. 실제 검사 | 문서 링크·저장소 검사·포털 모델 검사 | 검사 결과를 기록하고 실패를 숨기지 않음 |
| 6. 업로드 연결 | 저장소 이름·소유자·공개 범위에 맞는 remote 연결 | 실제 push 결과와 GitHub CI 결과 확인 |

1~5단계는 이번 로컬 정비 대상입니다. 6단계는 GitHub 대상 저장소를 정한 뒤 수행합니다. 문서 작성·로컬 검사 통과를 GitHub 업로드 또는 Sites 재배포 완료로 표시하지 않습니다.

이번 수행 결과: 1~5단계 완료. Git `main` 초기화와 첫 커밋 대상 준비까지 진행했고, 공개 대상 파일만 추출한 환경에서도 검사를 통과했습니다. 6단계의 원격 저장소 연결·커밋·push는 남아 있습니다.

## 다음 유지보수

1. 공개 전에 자체 코드·문서의 라이선스와 외부 자료의 재배포 범위를 결정합니다.
2. GitHub에 최초 업로드한 뒤 CI 실행 결과를 확인합니다. 사이트 공개를 원하면 별도의 배포 경로와 포함 파일을 정합니다.
3. 원본 JSON 변경 → 관련 검산 → 기존 통합 생성 → 포털 스냅샷 추출 → 문서 상태 갱신 순서를 유지합니다.
4. `tmp/pathways-release`에 의존하는 전체 생성 파이프라인을 정식 작업 경로로 옮기는 일은 별도 코드 변경으로 검토합니다. 현재 실행 스냅샷과 기존 생성 파이프라인은 [개발 안내](DEVELOPMENT.md)에 구분했습니다.
5. 구조 검사와 별도로 모바일·브라우저·인쇄 화면을 실제 확인합니다.

## 연구 후속 과제

독립 검토와 실제 학생 응답 검증, 미확보 원문·판본·정오표와 인용 원연구 대조를 계속 관리합니다. 필요한 근거가 없는 항목은 완료로 올리지 않습니다. 교육과정의 후속 개정 여부 조사도 기준 PDF의 버전과 분리하여 수행합니다.

정비 후 실제 검사 결과는 [검증 기록](VERIFICATION.md)에 남깁니다.
